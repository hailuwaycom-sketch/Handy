# /kanban — Tablero Kanban (tickets como shards)

Tablero Kanban con **ciclo de vida**: cada ticket es un shard con frontmatter
tipado (la fuente de verdad) y el board/tablas/métricas se **generan**, nunca se
editan a mano. La mecánica vive en el skill `backlog`
(`.claude/skills/backlog/SKILL.md`); este comando la orquesta y genera el
dashboard HTML.

> **Por qué shards y no un `KANBAN.md` monolítico:** un board editado a mano no
> tiene estado por ticket, ni velocity, ni auditoría de coherencia, y dos
> sesiones de agentes en paralelo chocan al tocar el mismo archivo. Con un shard
> por ticket + vistas generadas (`merge=union`), nada de eso pasa.

## Instrucciones

### Paso 1: ¿Ya hay backlog?

- Si existe `.claude/backlog/tickets/` → ese es el backlog. Seguí al Paso 3.
- Si no, y hay `USER-STORIES-*.md`, `BLUEPRINT-*.md` o `PIEZA-*.md` → **importá**:
  por cada story/tarea creá un shard (Paso 2).
- Si no hay nada → preguntá al usuario qué quiere trackear y creá el primer shard.

### Paso 2: Crear / importar tickets (shards)

Un ticket = un archivo en `.claude/backlog/tickets/<id>.md`. Plantilla en
`.claude/skills/backlog/templates/ticket.md`. Usá el script (stampá vos la fecha,
el script no la inventa para ser determinista):

```bash
node .claude/skills/backlog/backlog.mjs new --id T-001 --title "Login magic-link" \
     --kind story --pts 3 --priority alta --epic Auth --sprint S1 --date <hoy AAAA-MM-DD>
```

Frontmatter: `id · kind (story|bug|task|spike) · title · epic · pts · priority
(alta|media|baja) · status · sprint · blocked`. **Es lo único editable a mano.**

### Paso 3: Generar las vistas

```bash
node .claude/skills/backlog/backlog.mjs build
```

Esto valida los shards y regenera, desde ellos:
- el **board** + tablas por columna + **métricas** (dentro de `KANBAN.md`, solo
  entre `<!-- FORGE:BACKLOG:START -->` y `…:END -->`);
- `.claude/backlog/registry.yaml` (índice máquina-legible);
- asegura `merge=union` en `.gitattributes` para las vistas.

Si un shard está mal (id duplicado, status inválido, pts no numérico), `build`
falla ruidoso y **no** escribe vistas a medias — arreglá el shard y reintentá.

### Paso 4: Mover tickets

```bash
node .claude/skills/backlog/backlog.mjs move T-001 qa
```

Columnas: `backlog → planning → dev → qa → review → done`. Puede retroceder
(qa→dev si aparece un bug). Reglas de avance:
- **backlog → planning:** alguien la tomó para diseñar.
- **planning → dev:** tiene spec/diseño aprobado.
- **dev → qa:** código completo, sin TODOs.
- **qa → review:** tests pasan, build exitoso.
- **review → done:** aprobada y mergeada/deployada.

`move` edita el shard y regenera las vistas en un paso. **Nunca** muevas un ticket
editando el board.

### Paso 5: Dashboard HTML

Después de `build`, generá `.claude/reports/kanban-board.html` — un HTML
standalone (sin dependencias externas) estilo Trello, leyendo los datos de
`.claude/backlog/registry.yaml` (no parsees el board a ojo):

- **Layout:** 6 columnas lado a lado; header con emoji + nombre + count.
- **Cards:** ID, título, prioridad (borde izquierdo rojo/amarillo/verde), pts;
  🚫 si `blocked`.
- **Estilos inline:** header `#0079bf`, body `#f4f5f7`, columnas `#ebecf0`
  (min-width 250px, scroll horizontal), cards blancas con sombra. Stack vertical
  en mobile. Barra de progreso (% completado) en el header.
- **Footer:** timestamp + "Generated by Forge /kanban".

Es read-only; el usuario lo abre en el browser. Se regenera en cada cambio.

### Paso 6: "¿Cómo vamos?"

```bash
node .claude/skills/backlog/backlog.mjs stats
```

Conteos + velocity (pts/sprint de los tickets `done`; **n/a** si no hay campo
`sprint` — no se inventa un número).

## Integración con La Forja y El Yunque

- **El Yunque (Build Manual)** mueve tickets al transicionar de fase: `move <id>
  <status>` + regenerar el HTML.
- **La Forja (sandboxes paralelos)** se beneficia del `merge=union`: cada agente
  toca sus propios shards y regenera; las vistas se unen sin conflicto.

## Regla dura

El board, las tablas y las métricas son **vistas generadas**. Si te ves editándolas
a mano, pará: editá el shard y corré `build`. Eso es lo que hacía mentir al tablero
viejo.
