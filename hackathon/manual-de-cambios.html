FASE 01

Supresión de ruido (RNNoise)

Completada — commit 1507d2c ›

Línea de tiempo

  • 2026-07-08 20:49be5d3c1 — Paso 1/5: módulo NoiseSuppressor (RNNoise)
  • 2026-07-08 21:0724c80a9 — Pasos 2+3/5: enganche al pipeline + setting
  • 2026-07-08 21:12935f924 — Paso 4/5: toggle en Ajustes
  • 2026-07-11 19:461507d2c — Paso 5/5: validación manual con ruido estacionario real + tooltip actualizado con el alcance real de la feature

Backend

Handy no tenía ningún paso de reducción de ruido: el audio del micrófono iba directo del resampler al VAD/Whisper sin limpiar. Se agregó un módulo NoiseSuppressor (RNNoise vía nnnoiseless, que solo opera a 48kHz/480 muestras) puenteado con resampling bidireccional 16kHz↔48kHz (rubato), porque el pipeline de VozImperio corre a 16kHz.

Se engancha por sesión de grabación: recorder.rs construye un NoiseSuppressor nuevo cada vez que arranca una grabación con el toggle activo, y lo aplica a cada frame de 30ms antes de que llegue al VAD. Si falla al inicializar, la grabación sigue funcionando normal (passthrough) — nunca bloquea el dictado.

Efecto en el frontend: con el toggle activo, cada frame grabado pasa por RNNoise antes de llegar a Whisper — en teoría, transcripciones más limpias en ambientes con ruido de fondo constante (ventilador, teclado, tráfico).

Frontend

Toggle nuevo "Cancelación de Ruido" en Ajustes → Sonido, justo debajo del selector de micrófono — mismo componente visual (ToggleSwitch) que el resto de los switches de la app.

Dónde se configura

Ajustes → Sonido → Cancelación de Ruido

Ventaja

  • Handy stock no tiene ninguna forma de limpiar ruido de fondo antes de transcribir — esto es capacidad nueva, no una mejora de algo que ya existía.
  • Fallback seguro: si RNNoise falla al iniciar, la grabación no se rompe, simplemente no filtra ese frame.
  • Apagado por defecto — el resampling bidireccional cuesta CPU extra por frame, así que el costo solo se paga si el usuario lo activa.
  • Confirmado con oído real: validado dictando con ruido estacionario real (ventilador/hiss), toggle on/off — sin comerse voz real ni demora perceptible. Limitación real descubierta: no suprime música ni voces de fondo (RNNoise está entrenado para ruido estacionario), reflejado en el tooltip de Ajustes — ver cambios-de-configuracion-antes-de-fase-0.md.
FASE 02

Reparación de settings corruptos

Completada — commit dc4ea8d ›

Línea de tiempo

  • 2026-07-08 21:23dc4ea8d — Reparar campos corruptos en vez de resetear todo

Backend

Sin efecto visible en la UI en el día a día — esto es un cambio de resiliencia interna. Antes, si un solo campo de settings.json tenía el tipo equivocado (por ejemplo por una corrupción parcial de disco), serde_json::from_value fallaba completo y la app perdía TODOS los settings del usuario de un tirón — custom words, API keys, todo — reseteando a factory defaults sin avisar.

Ahora repair_settings_value() usa serde_path_to_error para ubicar el JSON-path exacto del campo que no parsea, lo elimina de ese valor (cada campo de AppSettings ya tiene #[serde(default = ...)], así que vuelve a su default en el siguiente intento) y reintenta hasta 20 veces. Solo cae a defaults completos si de verdad no se puede reparar. El valor corrupto original se respalda en la key settings_corrupted_backup del mismo store antes de sobreescribir, por si el repair adivinó mal.

Frontend

Ninguno — es puramente interno. El usuario nunca ve esta lógica correr.

Dónde se configura

No aplica — no es una opción, corre siempre automáticamente al cargar settings.

Ventaja

  • Handy stock no tiene ningún mecanismo de reparación — un solo campo corrupto borra todo. No aplica tabla antes/después porque no había ningún mecanismo previo con el que comparar, solo el reset total.
  • El usuario conserva su glosario, API keys y preferencias aunque un campo se corrompa — antes los perdía todos por igual.
  • El valor corrupto queda respaldado, no se pierde información para diagnosticar qué pasó.
FASE 03

Reemplazo de texto determinista

Funcional — validación manual pendiente ›

Línea de tiempo

  • 2026-07-11 15:2682f4a15 — Backend: regla de datos, motor de reemplazo y comando Tauri
  • 2026-07-11 15:310d71cdf — Bindings TypeScript regenerados
  • 2026-07-11 15:36b0223ab — Frontend: UI de reglas en Ajustes

Backend

Nueva regla de datos TextReplacementRule (find/replace/regex opcional/sensible a mayúsculas) y apply_text_replacements() en text.rs: en modo literal, el patrón de búsqueda se escapa antes de entrar al motor de regex (para que ., (, etc. no se interpreten como metacaracteres) y el reemplazo usa NoExpand para que un $1 literal no se expanda — solo el modo regex expande grupos de captura. Un regex inválido se salta con un aviso en vez de romper el resto del pipeline.

Se engancha al final de la misma función que ya corría el glosario fuzzy y el filtro de muletillas — es el último paso del post-proceso síncrono, y cubre tanto transcripción normal como streaming porque ambas rutas pasan por esa función.

Handy stock / VozImperio antes

El post-proceso terminaba en el filtro de muletillas — ningún patrón definido por el usuario se aplicaba después de transcribir.

VozImperio ahora

El texto pasa por las reglas de reemplazo del usuario como último paso, después del glosario y el filtro de muletillas.

Frontend

TextReplacementSettings.tsx (mismo patrón que Palabras Personalizadas): campo de búsqueda, campo de reemplazo, casillas "Regex" y "Sensible a mayúsculas", botón agregar. Las reglas ya creadas se listan debajo con badges cuando son regex o sensibles a mayúsculas, y botón para quitarlas.

Dónde se configura

Ajustes → Avanzado → Reemplazo de Texto (justo debajo de Palabras Personalizadas)

Ventaja

  • Handy stock no tiene ninguna forma de definir reemplazos de texto propios después de transcribir — esto es capacidad nueva.
  • Complementa al glosario fuzzy: el glosario corrige palabras sueltas por parecido fonético/ortográfico, esto reemplaza patrones exactos (o con regex) que el usuario define a propósito — útil para expandir abreviaciones o corregir frases completas, no solo palabras.
  • Un regex mal escrito no rompe el dictado: esa regla en particular simplemente no hace nada, el resto del pipeline sigue funcionando.
  • Validado con 11 tests unitarios (literal, regex con grupos de captura, sensibilidad a mayúsculas, regex inválido, orden de aplicación) — 118/118 tests del proyecto pasando, tsc limpio. Falta probar la UI corriendo la app de verdad, igual que la Fase 01.
FASE 04

AI Replace Selection

Funcional — validación manual pendiente ›

Línea de tiempo

  • 2026-07-11 16:36685f01a — Backend: captura de selección, transformación LLM, integración en el pipeline de grabación
  • 2026-07-11 16:36f4dd425 — Frontend: atajo en Ajustes + aviso cuando no hay selección

Backend

Selecciona texto en cualquier app, dicta una instrucción, y el mismo proveedor de IA ya configurado para post-procesamiento reescribe la selección en su lugar. Al presionar el atajo se simula Ctrl+X (nueva función send_cut_ctrl_x, espejo de la función de pegado que ya existía) para cortar la selección activa y leerla del portapapeles; si no había nada seleccionado, se restaura el portapapeles anterior y no llega a grabar nada. Después graba la instrucción hablada por el mismo pipeline que el dictado normal, la envía junto con el texto cortado al proveedor LLM, y pega el resultado.

Esta fase es distinta a las tres anteriores: en vez de un módulo aislado, necesitó extender TranscribeAction (antes un simple booleano post_process, ahora un enum de tres modos) porque reutiliza toda la orquestación de grabación que ya existía (overlay, bandeja del sistema, guardado de audio, cancelación) — solo se bifurca en el punto donde se decide qué texto pegar al final.

Handy stock / VozImperio antes

Un atajo de dictado siempre pega la transcripción tal cual (o pasada por un prompt fijo de post-procesamiento) donde esté el cursor — no existe manera de apuntar a un texto ya escrito en otro lado y transformarlo.

VozImperio ahora

Un atajo dedicado toma el texto que ya tenías seleccionado en cualquier aplicación, escucha una instrucción hablada sobre qué hacer con él, y devuelve el resultado transformado en el mismo lugar. Si la IA falla, se restaura el texto original — nunca se pierde nada.

Frontend

El atajo nuevo aparece junto al de post-procesamiento en Ajustes, mismo componente de captura de teclas que el resto de los atajos. Si se presiona sin tener nada seleccionado, aparece un aviso explicándolo — antes de este cambio no había ninguna señal, el atajo simplemente no hacía nada visible.

Dónde se configura

Ajustes → Post-Procesamiento → atajo "Reemplazar Selección con IA" — requiere tener post-procesamiento habilitado y un proveedor de IA configurado, porque reusa esa misma configuración.

Ventaja

  • Handy stock no tiene ninguna forma de transformar texto fuera de su propio flujo de dictado — esto es capacidad completamente nueva, no una mejora de algo existente.
  • No hace falta configurar un proveedor de IA aparte: reusa el mismo que ya se configuró para post-procesamiento.
  • Nunca se pierde el texto cortado: si la transformación falla por cualquier motivo (sin proveedor, sin modelo, error de red), se restaura la selección original tal cual estaba.
  • Es la fase de mayor riesgo de las cuatro: no hay tests automatizados posibles para la ruta principal (depende de Ctrl+X real del sistema operativo, portapapeles real, y una llamada de red real). Falta la prueba manual completa — seleccionar texto en otra app, dictar una instrucción, y confirmar que el resultado se pega bien.
FASE 05

Pausar media al dictar

Funcional — validación manual pendiente ›

Línea de tiempo

  • 2026-07-11 16:47f07d017 — Módulo de control de media, enganche en el ciclo de grabación, ajuste y toggle en la UI

Backend

Cuando empiezas a dictar, VozImperio le pregunta al sistema operativo qué sesiones de media están sonando en ese momento, pausa solo las que están reproduciéndose, y se guarda cuáles fueron. Al terminar el dictado reanuda exactamente esas — nunca destraba algo que ya estaba en pausa porque tú lo pausaste. La pausa ocurre en un hilo aparte para no sumar ni un milisegundo de retraso entre que presionas el atajo y arranca la captura del micrófono. Todas las vías de salida (terminar normal, error al grabar, cancelar) reanudan la media, así nunca queda colgada en pausa.

Handy stock / VozImperio antes

Si tenías música o un video sonando y dictabas, seguía sonando encima de tu voz — tenías que pausarlo a mano cada vez y acordarte de volver a ponerlo después.

VozImperio ahora

Al dictar, la música o el video se pausa solo y vuelve exactamente donde estaba al terminar. Si ya habías pausado algo por tu cuenta, no lo toca.

Frontend

Un interruptor nuevo en Ajustes → Sonido, junto a "Cancelación de Ruido" y "Silenciar al Grabar". Viene apagado por defecto para no sorprender a nadie pausándole la música sin avisar.

Dónde se configura

Ajustes → Sonido → "Pausar Media al Dictar" — apagado por defecto. Por ahora funciona en Windows.

Ventaja

  • Handy stock no tiene ninguna noción de la media del sistema — esto es capacidad completamente nueva.
  • Pausa solo lo que estaba sonando y reanuda solo eso: no arranca a reproducir algo que tenías en pausa a propósito, un problema típico de las soluciones que solo mandan la tecla "play/pausa" a ciegas.
  • No añade latencia al dictado: la pausa corre en segundo plano, la captura del micrófono no espera por ella.
  • Falta la prueba manual — dictar con música sonando y confirmar que se pausa al empezar, vuelve al soltar, y no toca lo que ya estaba pausado.

Qué es esta sincronización

La base liberó v0.9.1, una release de solo bug-fixes con ~31 aportes de la comunidad. Se adoptó completa con un merge del tag, preservando el 100% de lo VozImperio. 27 PRs entraron tal cual y 4 se resolvieron a mano por chocar con la marca o con features propias. Cero perdidos. Detalle PR por PR en cambios-de-configuracion-antes-de-fase-0.md.

Los 4 ajustes hechos a mano

v0.9.1 upstream

Agrega un selector de tema Claro / Oscuro / Sistema en Ajustes.

VozImperio

Se trae el mecanismo pero se fuerza la paleta imperial oscura en ambos modos y se oculta el selector: la marca queda dark siempre.

v0.9.1 upstream

Nuevo salvamento de settings corruptos (salva los campos válidos en vez de resetear todo).

VozImperio

Se adopta el de upstream y se descarta el nuestro equivalente (dc4ea8d): misma solución hecha en paralelo; alinearse reduce fricción a futuro.

Los otros dos: el reset de resampler anti-eco de upstream coexiste con nuestro supresor de ruido en cada grabación, y la cancelación de post-proceso colgado coexiste con AI Replace Selection.

Ganancia de build

Antes (transcribe-cpp 0.1.1)

El sub-build de shaders fallaba con "No CMAKE_C_COMPILER"; había que parchear a mano el caché de Cargo (parche frágil que se perdía con cada limpieza).

Ahora (0.1.2, con v0.9.1)

Compila limpio sin parche alguno — la dependencia nativa reescribió su detección de compilador.

Ventaja

  • Decenas de bug-fixes de la comunidad (anti-eco entre grabaciones, no abortar al salir, throttle de memoria del mic, defensa contra prompt-injection, tray visible en barras oscuras, y más) sin sacrificar ninguna feature ni la identidad visual VozImperio.
  • El build local dejó de necesitar un parche manual frágil: una fuente de fricción menos para cada compilación futura.
  • Validado: cargo build exit 0, tsc --noEmit 0 errores, bindings regenerados como fuente de verdad.
